# Yahoo Mail Bridge

A tiny self-hosted HTTP API in front of Yahoo Mail (IMAP/SMTP). It exists for
one reason: assistants like Muse can't keep a Yahoo login, so this service
holds the Yahoo app password on infrastructure you control and exposes just
search / read / send over a token-authenticated API.

Your Yahoo credentials never leave the machine you deploy this on. The API
token is the only secret you ever share, and you can rotate it any time.

## How it works

```
You -> deploy this on Render (free) -> set 3 env vars -> share the URL + API token
Muse -> calls https://your-service.onrender.com/v1/search with the token
Service -> talks IMAP/SMTP to Yahoo using the app password in its own env
```

## Deploy (about 5 minutes)

1. **Get a Yahoo app password**: Yahoo Account Security → "Generate app
   password" → choose "Other app", name it e.g. `mail-bridge` → copy the
   16-character password.
2. **Push this repo to GitHub** (or fork it), then go to
   [Render](https://render.com) → New → Blueprint → point it at the repo.
   `render.yaml` configures everything; the free plan is enough.
3. **Set the env vars** in Render (the blueprint asks for them):
   - `YAHOO_EMAIL` — your Yahoo address
   - `YAHOO_APP_PASSWORD` — the 16-character password from step 1
   - `API_TOKEN` — auto-generated by Render; copy it somewhere safe
4. Open `https://<your-service>.onrender.com/health` — you should see
   `{"ok": true}`.

## API

All `/v1/*` endpoints need `Authorization: Bearer <API_TOKEN>`.

| Method | Endpoint | What it does |
|---|---|---|
| GET | `/health` | Liveness check (no auth) |
| GET | `/v1/folders` | List mailboxes |
| GET | `/v1/search?mailbox=INBOX&q=from:amazon&limit=50` | Search. `q` supports `from:`, `subject:`, `to:` prefixes or free text |
| GET | `/v1/read?mailbox=INBOX&uid=123` | Full headers + plain-text body of one message |
| POST | `/v1/send` | JSON `{"to": "...", "subject": "...", "body": "..."}` |

Responses are small JSON — no HTML, no scraping.

## Run locally with Docker

```bash
cp .env.example .env   # then fill in your values
docker build -t yahoo-mail-bridge .
docker run --env-file .env -p 8000:8000 yahoo-mail-bridge
```

## Security notes

- Every `/v1/*` request is checked against `API_TOKEN`. Wrong token → 401.
- The Yahoo app password is only ever in the host's environment variables.
  It is never logged, never returned by any endpoint, never written to disk.
- Sends are deliberately plain — no bulk mode, no attachments endpoint.
- Rotate `API_TOKEN` in Render any time; update whoever holds the old one.
